🔧 底层数据结构规范

单本书本体 ↔ 历史全景本体 · 三层架构 + 四级溯源 + 统一ID空间

一、整体架构：三层本体+统一ID空间

整个本体体系采用严格的三层结构，每层拥有独立命名空间，通过全局ID统一关联，自下而上聚合，自上而下溯源：

L3 历史全景层

🌐 全局统一实体层

命名空间：global:    存储路径：/data/global/

核心实体：统一人物、统一事件、统一地理、统一制度/官职、统一朝代年表、跨书关系库

核心能力：跨书去重对齐、异文保留、因果关系贯通、制度沿革追踪、史料溯源互证、全局统计推论

↕ recorded_in / same_as / evidence
L2 单本书本体层

📕 单书视角实体层

命名空间：book:{book_id}:    存储路径：/data/books/{book_id}/

核心实体：书目元数据、篇章/卷次体例单元、注疏条目、作者版本、该书内出现的人物/事件/地理（未去重）

核心能力：按书建模、体例差异化（纪传/编年/纪事本末）、版本校勘、注疏归属、保留原书面貌

↕ in_chapter / in_sentence / target_sent_id
L1 原始文本层

📄 原始文本与批注层

命名空间：text:{book_id}:    存储路径：/data/books/{book_id}/

核心文件：chapters.json（篇章结构）、text.json（纯正文逐句编号）、annotations.json（独立批注库）

核心能力：正文批注分离、逐句唯一定位、版本原始面貌保留、为上层所有实体提供原文锚点

核心设计原则： 原始文本层永远不修改，所有校勘、对齐、推论都在上层完成；所有上层实体必须锚定到原文句子ID，保证"无一字无来处"。

二、命名空间与全局ID规范

所有实体必须拥有唯一全局ID，格式严格遵守：{namespace}:{type}:{slug}

层级命名空间ID示例说明
L3 全景层globalglobal:person:liubei统一人物，name做拼音slug
global:event:chibi_battle_208ad统一事件，{slug}_{年份}
global:place:chibi统一地理，古地名+今地名
global:institution:keju统一制度/官职
global:dynasty:han_west统一朝代/时期
L2 单本层book:{book_id}book:shiji:chapter:benji01史记第一篇本纪
book:shiji:annotation:000001史记第1条注疏
book:hanshu:juan:001汉书第一卷
L1 文本层text:{book_id}text:shiji:sentence:benji01_001史记·五帝本纪第1句

ID规则

1. 所有ID使用英文小写拼音/英文slug，不得含中文、空格、特殊字符
2. 历史全景层同一实体只有一个global_id，所有书中的对应条目均映射到这个ID
3. 单本书层ID前缀必须带book_id，避免跨书ID冲突
4. 文本层句子ID必须包含篇章ID，便于无需查表即可快速定位章节

三、各层核心数据结构定义

3.1 L1 原始文本层

1. 篇章结构文件 /data/books/{book_id}/chapters.json

// 定义一书的卷次、篇目、体例分类
{
  "book_id": "shiji",
  "structure_type": "jizhuan", // jizhuan纪传/biannian编年/jishi本末
  "volumes": [{
    "juan_id": "book:shiji:juan:001",
    "juan_number": 1,
    "juan_name": "五帝本纪第一",
    "category": "benji", // benji/biao/shu/shijia/liezhuan
    "chapter_id": "book:shiji:chapter:benji01"
  }]
}

2. 纯正文文件 /data/books/{book_id}/text.json

// 正文完全纯净，无任何注标标记，逐句带唯一ID
{
  "chapter_id": "book:shiji:chapter:benji01",
  "paragraphs": [{
    "para_id": "text:shiji:para:benji01_p001",
    "sentences": [{
      "sent_id": "text:shiji:sentence:benji01_001",
      "text": "黄帝者，少典之子，姓公孙，名曰轩辕。",
      "order_in_chapter": 1
    }]
  }]
}

3. 批注文件 /data/books/{book_id}/annotations.json

// 批注完全独立，通过target_sent_id绑定到正文句
{
  "annotations": [{
    "anno_id": "book:shiji:annotation:000001",
    "annotator": "裴骃",
    "anno_type": "jijie", // jijie集解/suoyin索隐/zhengyi正义/hu胡注/yan颜注/pei裴注
    "target_sent_id": "text:shiji:sentence:benji01_001",
    "content": "少典，有熊氏国君也。",
    "source_version": "武英殿本三家注史记"
  }]
}

3.2 L2 单本书本体层

1. 书目元数据 /data/books/{book_id}/meta.json（记录作者、年代、卷数、体例、注本版本、覆盖时段）

2. 单本书内实体 /data/books/{book_id}/entities.json

// 单本书视角下的人物/事件/地理，保留原书记载，未做跨书去重
{
  "persons": [{
    "book_person_id": "book:shiji:person:huangdi",
    "name_in_book": "黄帝",
    "aliases_in_book": ["轩辕", "有熊氏"],
    "global_id": "global:person:huangdi", // 关联到全景层
    "first_appear_sent_id": "text:shiji:sentence:benji01_001"
  }],
  "events_in_book": [...]
}

3.3 L3 历史全景层

全局统一实体库，按类型分文件存储：

  • /data/global/persons.json：统一人物库，聚合所有书中对该人物的记载
  • /data/global/events.json：统一事件库，挂载所有史料来源与考异
  • /data/global/places.json：统一地理库，对应古今地名、政区沿革
  • /data/global/institutions.json：统一制度官职库，记录制度沿革脉络
  • /data/global/dynasties.json：统一朝代年表，所有时间坐标基准
  • /data/global/relations.json：跨书全局关系库（人物参与事件、事件因果、制度沿革等），每条关系必须带evidence

四、核心关联机制：四级溯源锚点

所有全局实体最终必须锚定到原文句子，形成完整可追溯链，保证"无一字无来处"：

🌐 global:person:huangdi   // 全景层统一黄帝实体
└── appear_in_books → book:shiji:person:huangdi   // 史记中记载的黄帝
└── first_appear → text:shiji:sentence:benji01_001   // 原文具体句子
└── 原文：黄帝者，少典之子，姓公孙，名曰轩辕。
└── 裴骃《集解》注：少典，有熊氏国君也。 // 对应批注

五、关联与校验规则

1. 向上聚合规则： 单本书实体可以映射到多个全局实体（异名同实），必须人工确认same_as_confirmed: true，未确认的不进入全局统计
2. 向下溯源规则： 所有全局实体的属性、关系，必须至少有一条evidence指向原文sent_id，无证据的关系不入库
3. 异文保留规则： 不同书对同一事件/人物的记载差异，存入variants_in_books字段，绝不覆盖原书记载
4. 考异机制： 司马光《资治通鉴考异》类条目直接作为kaoyi字段挂载到全局事件下，作为史学考证证据，不混入正文
5. 注疏关联规则： 注疏通过target_sent_id间接关联到全局实体，可额外标注related_global_entity直接关联到人物/地理/制度
6. 原始不变规则： L1文本层文件一旦录入永不修改，所有校勘、考证、对齐都在L2/L3层完成

七、落地步骤

M1

规范与基础完成

Schema规范发布、底层目录结构搭建、史记/资治通鉴L1文本+批注分离完成。

M2

史记样板跑通

抽取史记中100个核心人物、50个核心事件，对齐到全局层，形成完整可运行的样本，验证四级溯源链。

M3

前四史批量对齐

开发半自动对齐工具，完成汉书、后汉书、三国志的实体抽取与全局对齐。

M4

历史全景统计上线

基于全局库开发可视化统计面板，上线各类跨书统计、因果链、沿革图谱。

M5

全量覆盖

完成二十四史+资治通鉴全部实体对齐，注疏关联全局实体，支持点击注疏直接跳转对应人物/地理/制度页面。
